# 自动维护策略

自动维护是受治理约束的贡献者，不拥有绕过质量门禁的权限。

## 运行节奏

- 目标检查窗口：北京时间凌晨 1 点，约每两天一次。
- 一次运行最多推进一个教学版本。
- 质量不足时允许只创建或更新草稿 PR，不创建空 tag 或空 Release。

## 强制流程

1. 拉取 `main` 并确认工作区状态。
2. 创建 `codex/` 前缀分支，绝不直接修改远端 `main`。
3. 只处理 Roadmap 中下一个未完成版本。
4. 运行全部相关门禁并保存可复现证据。
5. 推送分支并创建 PR；等待 CI 通过。
6. 不覆盖用户修改，不 force-push，不绕过 required checks。
7. 合并后才允许创建语义化 tag 和 GitHub Release。

## 安全边界

- 不读取、记录或提交 API Key、OAuth token、Cookie、个人文件、浏览历史或真实 Session。
- 不修改首仓 `pi-agent-from-zero` 或任何上游参考仓库。
- 外部网络和真实模型默认关闭；只有明确、无秘密的测试配置才能启用。
- GitHub 鉴权、CI、分支保护或网络阻塞时保留本地验证结果并停止，不降级安全策略。
