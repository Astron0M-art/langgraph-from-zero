# 自动维护策略

本仓库由 Codex 自动提出和实现维护候选。自动化不伪装成人工作者，不编造学习心得、用户反馈、生产
事故或外部 Review，也不拥有绕过质量门禁的权限。

## 运行节奏

- 启动窗口：北京时间每月双数日期 `00:00`。
- `00:00` 是维护流程的启动时间；审计、CI 和发布可以在其后完成。
- 一次运行最多推进一个教学版本。
- 质量不足时允许只创建或更新草稿 PR，不创建空 tag 或空 Release。

## 强制流程

1. 拉取 `main` 并核对工作区、开放 PR、CI、分支保护、tag 和 Release。
2. Maintainer 提出候选；全新只读 Scope Editor 选择一个问题或返回 `NO_RELEASE`。
3. 创建 `codex/` 前缀分支和 AI-assisted Draft PR，绝不直接修改远端 `main`。
4. 依次执行教学真实性、对抗性工程、干净环境发布复验三轮上下文隔离的只读 AI 审计。
5. 每轮公开候选 SHA、文件、命令、分级发现、结论和残余风险；AI 审计不等于人工 Review。
6. 三轮与 required checks 全绿后才允许合并；合并后 `main` CI 全绿才允许 tag 和 Release。
7. 不覆盖用户修改，不 force-push，不绕过 required checks；任一硬门禁失败时保留 Draft 并停止发布。

## 累计演进门禁

- `vN` 必须保留 `vN-1` 的全部已验证行为，只新增一个运行时语义。
- 最新能力必须进入同一套 `src/` 与默认 CLI；只新增 lesson 或复制另一套图引擎属于阻断项。
- lesson snapshot 是截至该版本的累计实现；可独立运行只表示不依赖未来代码。
- 每次发布同时验证新增行为、全部历史回归，以及至少一条组合两项以上既有能力的累计端到端路径。
- API、CLI、state schema 与 checkpoint 格式不得静默失效；必要变化必须提供迁移说明和测试。

## 安全边界

- 不读取、记录或提交 API Key、OAuth token、Cookie、个人文件、浏览历史或真实 Session。
- 不修改首仓 `pi-agent-from-zero` 或任何上游参考仓库。
- 外部网络和真实模型默认关闭；只有明确、无秘密的测试配置才能启用。
- GitHub 鉴权、CI、分支保护或网络阻塞时保留本地验证结果并停止，不降级安全策略。
